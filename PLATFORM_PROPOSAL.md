# Proposed browser platform catalog

**Review draft only — September 27, 2026. No additions have been made to the built-in platform list.**

This first proposal contains 42 additions, plus the 4 existing entries: 46 total. It is a broad catalog, not an exhaustive worldwide registry. Broker-branded and regional deployments can use different hosts.

The sources below establish public platform entry points or official outbound links. They do **not** establish authenticated compatibility with Haki, account availability in every country, or endorsement of a provider. Verify post-login redirects and test the gate before shipping an approved entry. Each hostname would be opt-in and require its own permission; there is no proposal to request access to all of them automatically.

## Implementation proposal after user approval

1. Add search and group filters so the larger catalog remains easy to browse. Existing choices and rules must survive the update.
2. Keep new sites off by default and request only the exact origin the user enables. No subdomain wildcards; country variants get explicit hosts.
3. Increase or separate the existing 50-website limit so the expanded built-in catalog does not crowd out custom websites. This has not been changed.
4. Where one platform uses multiple terminal hosts, model them explicitly with permission-aware migration rather than silently protecting broad company domains. Some account domains (for example Fidelity) also contain non-trading pages; show users the scope of protection.
5. Validate each approved entry with authenticated demo/safe-account navigation, first-paint blocking, confirmation, reload, manual gate and emergency access. Public URL research is not a substitute for these checks.
6. Keep all user-created custom websites available for unlisted and regional platforms.

The requested review comes before any catalog, storage-limit, permission or platform UI changes.
